# 二十一协作区个人主体小程序开发需求文档（无独立后台版）

> 文档版本：V2.0  
> 编制日期：2026年6月11日  
> 适用主体：个人主体微信小程序  
> 建设方式：仅微信小程序端，不建设独立网页管理后台  
> 保密要求：包含成员、企业、关爱及内部活动资料，请勿外发

## 一、结论与推荐方案

本项目可以采用个人主体微信小程序上线，也可以不建设电脑网页管理后台、不购买或维护阿里云服务器。

但“不要自己管理数据库和服务器”不等于“系统完全不需要云端数据存储”。120至200名成员需要共享待办、活动、照片、成员资料和历史记录，必须有一个公共云端保存位置。

推荐采用：

```text
微信小程序
    ↓
微信云开发（微信托管）
    ├─ 云数据库：保存活动、成员、岗位、历史和权限
    ├─ 云存储：保存活动照片和附件
    └─ 云函数：完成微信身份识别和敏感权限校验
```

项目负责人不需要安装、配置或维护MySQL、Node.js、Nginx、域名、SSL证书和阿里云服务器。日常工作全部在小程序内完成。

## 二、为什么不能完全不要云端存储

如果不使用任何数据库、云存储或服务器，只能制作“静态展示版”：

- 内容写死在代码中。
- 只有重新修改代码、上传版本、重新审核后才能更新。
- 多人不能共同上传和维护资料。
- 手机上新增的活动、照片和成员信息不能可靠同步给其他人。
- 删除小程序或更换手机后，本地信息可能丢失。
- 无法实现真正的成员权限、岗位轮换和操作记录。

因此，正式版必须使用云端数据。微信云开发属于低运维方案，项目负责人不需要直接操作传统数据库。

## 三、个人主体上线的主要影响

### 3.1 可以保留的功能

以下功能与个人主体的“工具—办公、日历、信息查询、预约/报名、备忘录”等类目较为匹配，可以继续开发：

| 功能 | 是否保留 | 调整说明 |
|---|---:|---|
| 首页月度日历与待办 | 保留 | 定位为内部协作和备忘工具 |
| 公益服务活动记录 | 保留 | 记录事实，不开展公开募捐 |
| 活动照片相册 | 保留 | 登录成员可见，避免公开传播敏感照片 |
| 四个服务队展示 | 保留 | 作为内部组织分类，不宣称政府或法定机构 |
| 生日提醒 | 保留 | 仅展示月日，不默认展示出生年份 |
| 聚会、联谊和会议记录 | 保留 | 仅内部使用 |
| 狮友个人资料 | 限制保留 | 最少收集、本人授权、分级可见 |
| 企业与行业资源 | 限制保留 | 经成员同意后展示，避免公开营销交易 |
| 协作区及四队发展历史 | 保留 | 作为内部档案和信息查询 |
| 年度届次与岗位 | 保留 | 用于权限和历史记录 |
| 小程序内管理页面 | 保留 | 不建设独立网页后台 |
| 微信身份绑定 | 保留 | 由云开发获取用户身份并绑定内部成员 |

### 3.2 建议删除或暂缓的功能

| 原计划功能 | 个人主体影响 | 调整方案 |
|---|---|---|
| 在线捐款、公益募捐 | 高风险，不适合个人主体直接开展 | 首版完全删除，不显示金额、收款码和捐款入口 |
| 账目明细对全员公开 | 容易产生财务、募捐和隐私风险 | 不纳入首版；确需保存时仅授权管理员查看 |
| 公开招募社会人员 | 可能超出内部工具定位 | 只允许管理员预录成员或发放内部授权码 |
| 对外公开的会员申请 | 容易变成组织招募或社交平台 | 删除“申请加入”，改为管理员后台添加 |
| 公开动态、评论和群聊 | 涉及用户生成内容传播及内容安全 | 首版不做评论、论坛、群聊和公开投稿 |
| 新闻稿投稿平台 | 可能形成公开内容发布平台 | 改为管理员维护的活动总结 |
| 在线培训视频、直播 | 可能需要教育或直播类目资质 | 首版只保存培训时间、主题、照片和文字纪要 |
| 医疗健康咨询 | 个人主体不具备医疗资质 | 关爱模块不得提供诊断、问诊或治疗建议 |
| 商城、在线交易、会员收费 | 涉及交易和支付能力 | 首版不做 |
| 对外展示完整通讯录 | 存在严重个人信息风险 | 仅绑定成员按权限查看，禁止游客访问 |

### 3.3 小程序名称与介绍的影响

个人主体注册时，小程序名称、简介和页面内容应避免让用户误认为这是政府、社会团体、公益基金会或其他依法登记机构的官方平台。

建议名称：

```text
二十一协作区记事本
二十一协作区服务档案
二十一协作区协作记录
```

建议简介：

```text
用于记录四个服务队的内部协作待办、公益活动、照片和发展历史。
```

不建议在个人主体介绍中使用“官方”“基金会”“募捐平台”“公益组织管理平台”等容易产生主体资质误解的表述。

最终名称和类目必须以微信公众平台提交时的审核结果为准。

## 四、调整后的产品定位

本项目定位为约120至200人使用的内部公益服务档案与协作工具，不设计成大型会员办公管理系统。

保留：

- 月度日历和协作待办
- 公益服务、关爱、生日、聚会和会议记录
- 四个服务队入口
- 活动照片档案
- 成员及企业资源
- 发展历史
- 年度岗位与权限

不展示：

- 会员编号
- 捐款金额
- 积分
- 服务时长
- 培训时长
- 勋章和绩效排名
- 公开入会申请
- 稿件投稿
- 报表中心

### 4.1 最终导航结构

底部导航固定为：

1. **首页**：集中展示本月待办、生日、关爱、通知和组织架构入口。
2. **历史事件**：自动汇总各岗位档案中具有日期和事件属性的内容。
3. **档案**：按二十一协作区及四个服务队分别维护岗位资料。
4. **通讯录**：按姓氏拼音排序展示狮友和所属服务队。
5. **我的**：身份、权限、通知和管理中心。

月度事项页面不展示完整月份的空白日历，只展示存在待办事项的日期。

### 4.2 主目录与五套档案

“记事本总目录”是每个组织的档案入口。系统分别建立：

1. 二十一协作区档案
2. 领航服务队档案
3. 爱领航服务队档案
4. 远航服务队档案
5. 精英服务队档案

每套档案包含：

- 记事本总目录
- 会员发展
- 领导力与培训
- 公益服务
- 年度服务计划
- 会议纪要
- 对外交流
- 新闻宣传
- 狮友关爱
- 聚会联谊
- 物品清单
- 账目档案
- 独立照片云盘

通讯录不放入档案目录，使用单独页面统一管理。

账目档案仅司库与最高管理员可见。

### 4.3 档案录入与历史事件

档案内容不以上传PDF附件为主要方式。岗位人员直接在小程序表单中填写：

- 日期
- 标题
- 档案类型
- 所属组织
- 负责人
- 参与人员
- 地点
- 正文或总结
- 照片
- 可见范围

保存后进入本组织档案。具有日期和事件属性的内容自动进入“历史事件”页面，无需再次录入。

所有待办和历史事件卡片末尾必须明确显示“二十一协作区”或具体服务队名称。

### 4.4 组织架构

小程序设置独立组织架构模块：

```text
二十一协作区
    ↓
领航、爱领航、远航、精英四个服务队
    ↓
队长团队
    ↓
各委员会主席及岗位
```

组织架构按年度届次切换，历史架构不得被新一届覆盖。

### 4.5 狮友通讯录

- 页面名称统一为“狮友通讯录”。
- 按姓氏拼音首字母排序。
- 姓名右侧明确显示所属服务队。
- 页面右侧提供A至Z首拼索引。
- 点击或上下滑动索引时跳转到对应姓氏分组。
- 当前所在字母自动放大显示。
- 支持按姓名、服务队、岗位、企业和资源检索。
- 手机号码和详细地址仍按成员权限控制。

### 4.6 照片云盘

二十一协作区及四个服务队分别设置照片上传区。

- 新闻宣传角色负责集中上传。
- 上传照片时选择所属活动或新建事件。
- 支持批量上传、封面、说明和缺图提醒。
- 照片归入本组织档案，并可关联历史事件。
- 联合活动照片只上传一次，可同时关联多个组织。

## 五、用户与权限

### 5.1 用户类型

| 用户 | 权限 |
|---|---|
| 未绑定访客 | 只能看到项目说明、隐私说明和身份绑定入口 |
| 普通成员 | 查看允许公开给内部成员的待办、活动、照片和历史 |
| 岗位管理员 | 维护本人岗位负责的内容 |
| 服务队管理员 | 管理本队活动、成员和岗位 |
| 协作区管理员 | 管理四队公共内容 |
| 超级管理员 | 管理身份绑定、岗位、权限和全部数据 |

### 5.2 成员绑定

推荐流程：

1. 管理员先在小程序内录入成员姓名和所属服务队。
2. 成员首次打开小程序，阅读并同意隐私保护指引。
3. 成员输入姓名和内部授权码。
4. 云函数识别微信用户身份并绑定成员档案。
5. 未绑定用户不能查看通讯录、关爱详情和内部照片。

不要求普通成员提交身份证号码。

### 5.3 权限校验

权限不能只靠隐藏按钮。每次读取或修改敏感信息时，云函数必须重新检查：

- 当前微信用户
- 所属服务队
- 当前届次
- 当前岗位
- 数据可见范围

## 六、首页与月度待办

首页第一屏展示：

1. 二十一协作区名称和当前届次。
2. 领航、爱领航、远航、精英四个服务队。
3. 本月公益服务。
4. 本月狮友关爱安排。
5. 本月生日。
6. 聚会、联谊、会议和换届事项。
7. 最近活动和照片。

待办字段：

- 标题
- 类型
- 日期和时间
- 所属组织
- 负责人
- 地点
- 简要说明
- 状态
- 可见范围
- 是否转为活动档案

## 七、活动与照片档案

活动类型：

- 公益服务
- 狮友关爱
- 狮友生日
- 聚会联谊
- 会议纪要
- 培训记录
- 对外交流
- 宣传记录
- 换届与组织历史

每项活动可以保存：

- 活动名称
- 日期、地点
- 所属服务队
- 负责人和参与人员
- 过程记录和活动总结
- 封面照片
- 活动相册
- 可见范围

照片直接上传到微信云存储。小程序显示压缩图，需要时再预览大图。

建议限制：

- 单次选择最多9张，允许连续上传。
- 每张展示图建议压缩到500KB至1.5MB。
- 关爱类照片默认仅相关岗位可见。
- 不上传身份证、病历、银行卡和其他不必要的敏感证件照片。

## 八、成员、企业与关爱信息

### 8.1 成员信息

首版建议只保存：

- 姓名
- 头像
- 所属服务队
- 当前岗位
- 加入日期
- 生日月日
- 联系电话（可选且按权限显示）
- 企业名称、行业和可提供资源（经本人同意）

不收集身份证号、家庭住址和银行卡信息。

### 8.2 狮友关爱

关爱记录可能涉及健康、家庭和困难信息，属于高敏感内容。

首版处理原则：

- 普通成员只看到“有关爱安排”，不显示原因。
- 只有关爱岗位和授权管理员可查看详情。
- 健康情况使用概括性文字，不上传病历和诊断资料。
- 不在通知标题中显示疾病、家庭困难或经济情况。
- 关爱数据不可通过搜索、分享或截图水印外传。
- 正式使用前取得被关爱成员或相关人员同意。

## 九、小程序内管理中心

不开发独立网页后台，所有管理功能放在小程序“我的—管理中心”。

管理功能包括：

- 新增和修改月度待办
- 新增活动和会议记录
- 批量上传活动照片
- 维护成员和企业资料
- 管理四个服务队
- 创建年度届次
- 调整岗位和任职人员
- 设置内容可见范围
- 发布内部通知
- 管理发展历史
- 查看近期操作记录
- 将误删内容恢复

手机批量录入大量历史资料会比电脑慢，但不影响功能实现。后续仍坚持只使用小程序时，可以通过分批录入和Excel导入文件的方式降低工作量；Excel仅作为导入文件，不建设网页后台。

## 十、信息更新方式

### 10.1 不建议每次都改代码

如果每次修改活动、照片、成员或通知都找开发人员改代码，会产生以下问题：

- 每次修改都需要重新上传版本。
- 部分修改需要重新提交审核。
- 审核期间信息不能立即更新。
- 历史资料越来越多后，代码包会过大。
- 照片不能长期写进小程序代码包。

### 10.2 正确方式

程序功能变化才修改代码，例如新增一个全新模块。

日常信息变化直接在小程序管理中心完成，例如：

- 新增活动
- 修改日期和地点
- 上传照片
- 调整成员岗位
- 发布通知
- 补充历史记录

这些数据修改通常不需要重新发布小程序版本。

## 十一、微信云开发方案

### 11.1 云数据库集合

| 集合 | 用途 |
|---|---|
| `organizations` | 协作区和四个服务队 |
| `members` | 成员资料及微信绑定 |
| `enterprises` | 成员企业和资源 |
| `terms` | 年度届次 |
| `appointments` | 历年岗位任职 |
| `tasks` | 月度待办 |
| `events` | 活动与会议档案 |
| `photos` | 照片信息和云文件ID |
| `care_records` | 授权可见的关爱记录 |
| `notices` | 内部通知 |
| `history` | 协作区和四队发展历史 |
| `audit_logs` | 管理员操作记录 |

### 11.2 云函数

首版建议使用以下云函数：

- 用户登录与OPENID识别
- 成员授权码绑定
- 权限检查
- 活动和照片管理
- 岗位换届
- 敏感信息读取
- 管理员操作记录
- 定期数据备份

### 11.3 项目负责人需要做什么

项目负责人只需要：

- 使用微信公众平台管理版本和体验成员
- 在小程序管理中心维护日常资料
- 定期查看云开发资源用量和账单
- 每年确认新届次和岗位人员
- 联系开发人员处理功能升级或异常

不需要自行维护服务器、数据库程序、域名和证书。

## 十二、个人主体审核方案

建议服务类目优先考虑：

- 工具—办公
- 工具—日历
- 工具—信息查询
- 工具—预约/报名
- 工具—备忘录

最终类目以微信公众平台提交时开放的类目和审核意见为准。

审核材料和页面应保持一致：

- 小程序介绍为内部协作记录工具。
- 不出现在线捐款、收款码和公开募捐。
- 不提供医疗问诊、健康诊断和治疗建议。
- 不提供公开聊天、论坛、评论和社会人员自由注册。
- 不把个人主体包装为政府或依法登记社会组织的官方账号。
- 演示账号准备完整，审核人员能够正常进入主要页面。
- 隐私保护指引真实列明所收集的信息及用途。

## 十三、隐私与合规

小程序处理个人信息时，必须配置《小程序用户隐私保护指引》，并在收集信息前明显提示用户阅读和同意。

需要说明的信息包括：

- 微信用户身份标识
- 用户填写的姓名
- 用户选择的头像
- 手机号码（如启用）
- 用户选择上传的照片
- 所属服务队、岗位、企业和生日信息

隐私页面应提供：

- 收集目的
- 使用范围
- 保存期限
- 联系方式
- 信息更正方式
- 账号解绑或删除申请方式

通讯录、关爱和企业联系方式不得向未绑定用户公开。

## 十四、数据备份与防误删

即使使用微信云开发，也必须设计备份：

- 删除数据先进入回收站，保留30天。
- 关键集合每周导出一次备份。
- 每月保存一份长期备份。
- 活动照片保留云文件ID与活动关系。
- 岗位换届不得覆盖上一届记录。
- 重要操作写入日志。

备份操作可以由开发人员协助完成，不要求项目负责人维护服务器。

## 十五、成本与维护

不建设网页后台、不使用阿里云服务器后，可以取消：

- 阿里云服务器续费
- MySQL维护
- 域名续费
- SSL证书维护
- OSS单独配置
- 网页后台开发费用

仍可能发生：

- 微信云开发资源费用
- 云存储和图片下载流量费用
- 超出免费或基础额度后的数据库、云函数调用费用
- 后续功能修改和维护费用

云开发支持按量计费，实际费用以微信云开发控制台当时显示为准。照片数量和访问量是主要成本来源。

## 十六、开发阶段

### 第一阶段：个人主体可审核版本

- 微信身份识别
- 成员授权码绑定
- 首页日历和月度待办
- 四队展示
- 活动档案
- 照片上传
- 隐私保护指引

### 第二阶段：内部资料

- 成员和企业资料
- 生日提醒
- 关爱权限
- 会议、培训和联谊记录
- 协作区及四队发展历史

### 第三阶段：管理与换届

- 小程序管理中心
- 届次和岗位
- 操作记录
- 回收站
- 数据备份

## 十七、首版验收标准

- [ ] 个人主体可选择的服务类目与实际页面内容一致。
- [ ] 未绑定人员不能查看内部照片、成员和关爱资料。
- [ ] 管理员可以直接在小程序内新增和修改日常信息。
- [ ] 日常资料修改不需要重新改代码。
- [ ] 四个服务队可以分别筛选。
- [ ] 首页可以查看本月公益、关爱、生日和联谊事项。
- [ ] 活动可以上传照片并设置封面。
- [ ] 成员信息按权限展示。
- [ ] 关爱详情只有授权岗位可以查看。
- [ ] 每年换届不覆盖历史岗位。
- [ ] 删除内容可以恢复。
- [ ] 管理操作具有记录。
- [ ] 30人以内同时使用时运行稳定。
- [ ] 正式上线前完成隐私保护指引和小程序备案要求。

## 十八、最终建议

以个人主体上线，可以完成大部分“内部记录、日历待办、活动照片、成员企业、发展历史和岗位管理”功能。

最合适的实施方案是：

```text
个人主体微信小程序
+ 微信云开发
+ 小程序内管理中心
- 独立网页后台
- 阿里云服务器
- 在线捐款
- 公开会员申请
- 公开评论和群聊
```

该方案能最大限度降低维护工作，但仍需要开发人员完成首次云开发配置、安全规则、数据结构和管理功能。正式运行后，项目负责人只需通过小程序维护日常资料。

   https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/PrivacyAuthorize.html
