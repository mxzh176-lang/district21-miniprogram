# 21纪事本产品改版设计 v1

## 1. 改版目标

本次改版将小程序从“多个功能入口并列”调整为“以当前组织范围为中心”的内部管理工具。

核心原则：

- 用户先确定当前查看范围：`二十一协作区` 或某个 `服务队`。
- 首页、待办、档案、成员、荣誉、权限入口都跟随当前范围变化。
- 保持个人主体小程序审核安全，不加入公开社交、评论、聊天、论坛、点赞、关注、公开发布、支付或募捐能力。

## 2. 全局组织范围

### 2.1 可选范围

第一阶段固定支持：

- 二十一协作区
- 领航服务队
- 爱领航服务队
- 远航服务队
- 精英服务队

### 2.2 展示位置

首页顶部左上角常驻显示：

```text
二十一协作区 ▼
```

或当前服务队：

```text
远航服务队 ▼
```

点击后弹出范围列表。用户选择后，将当前范围保存为全局状态，后续进入首页、待办、档案、成员等页面时沿用该范围。

### 2.3 设计要求

- 切换器不能藏在轮播图标题里，必须常驻、明显、可点击。
- 不使用“全国”等容易扩大运营范围或引发审核误解的文案。
- 当前范围只用于内部数据筛选，不形成公开区域站点或公共信息发布平台。

## 3. 底部导航

第一阶段底部导航调整为：

```text
首页 / 待办 / 档案 / 成员 / 我的
```

页面对应关系：

| 导航 | 页面 | 说明 |
| --- | --- | --- |
| 首页 | `pages/home/index` | 当前范围总览、快捷入口 |
| 待办 | `pages/tasks/index` | 当前范围内重点待办 |
| 档案 | `pages/archive/index` | 当前范围内岗位档案、历史事件、荣誉入口 |
| 成员 | `pages/org/index` | 当前范围内成员名册 |
| 我的 | `pages/profile/index` | 我的身份、岗位、权限和管理入口 |

历史事件不再单独占底部导航，作为首页和档案内的业务入口保留。

## 4. 首页设计

首页围绕当前范围展示：

- 当前范围名称与切换入口
- 成员数量
- 服务队数量或当前服务队标识
- 本月重点待办
- 荣誉与表彰入口
- 档案入口
- 最近历史事件或服务足迹
- 通知摘要

范围规则：

- 选择 `二十一协作区`：显示全部服务队汇总。
- 选择某个服务队：只显示该服务队数据。

## 5. 待办设计

待办页跟随当前范围：

- 协作区：显示全部服务队待办。
- 服务队：只显示本服务队待办。

待办分组：

- 今天
- 本周
- 本月
- 已完成

权限要求：

- 普通成员只查看。
- 管理员、待办管理人、创建人或对应岗位负责人可以新增、编辑、完成。
- 写操作必须由云函数再次鉴权，页面隐藏按钮不能代替权限控制。

## 6. 档案设计

档案页跟随当前范围：

- 协作区档案
- 服务队档案
- 岗位档案
- 历史事件
- 荣誉相关档案

荣誉档案流程：

```text
创建事件 → 负责人/队长确认 → 荣誉主席核准 → 荣誉墙展示
```

审核安全要求：

- 荣誉墙定位为内部表彰档案，不做公开排行榜或社交榜单。
- 不提供评论、点赞、关注、分享信息流等互动能力。

## 7. 成员设计

成员页跟随当前范围：

- 协作区：显示全部服务队成员，可按服务队筛选。
- 服务队：只显示本服务队成员。

成员详情展示：

- 姓名
- 所属服务队
- 岗位
- 任期
- 权限摘要

隐私要求：

- 默认不收集身份证、人脸、证件照片、手机号等敏感信息。
- 内部身份资料不能描述为“实名认证”。

## 8. 我的与权限中心

“我的”页面展示：

- 我的姓名
- 我的服务队
- 我的岗位
- 我的权限摘要
- 我的待办入口
- 管理入口

权限中心不放到底部导航，继续作为管理入口，避免普通成员误认为这是普通功能页。

权限中心模块：

- 用户角色
- 服务队管理员
- 岗位负责人
- 荣誉主席
- 待办权限
- 档案权限
- 操作日志

## 9. 第一阶段实现清单

第一阶段只做结构清晰、风险低、能明显改善体验的改动：

1. 首页左上角新增常驻范围切换器。
2. 当前范围保存为全局状态。
3. 底部导航改为：`首页 / 待办 / 档案 / 成员 / 我的`。
4. 待办页读取当前范围并筛选数据。
5. 档案页读取当前范围并筛选数据。
6. 成员页读取当前范围并筛选数据。
7. 权限中心入口保留在“我的/管理入口”，不扩大普通成员权限。

## 10. 暂缓内容

以下内容暂不进入第一阶段：

- 公开内容广场
- 评论、点赞、关注、粉丝
- 开放聊天室或论坛
- 在线支付、报名收款、募捐
- 敏感身份认证
- 面向不特定公众的信息发布

## 11. 发布与验证要求

每次实现改版功能后必须验证：

- `git diff --check`
- JavaScript 语法检查
- 现有测试
- `miniprogram/app.json` JSON 合法性
- 页面层不直接调用数据库
- 页面层不自行拼接 `cloudPath`
- 如修改 `cloudfunctions/`，必须部署对应云函数后再测试

## 12. 审核影响结论

本设计为 `审核安全`：

- 产品定位仍是内部组织、岗位、档案、待办和成员管理工具。
- 不新增公开社交、开放式 UGC、评论、聊天、论坛、支付、募捐等高风险功能。
- 当前范围切换只用于内部数据筛选，不形成公开区域平台。
