# 远航每月例会联谊待办设计

## 审核影响

分类：`审核安全`。

本次新增的是远航服务队内部每月例会与联谊提醒，不增加公开内容、报名收费、社交互动或个人信息收集。所有待办仍限定在现有远航组织范围和既有读取权限内。

## 现状与目标

当前云函数只有生日和职业节日自动待办，没有每月 5 日例会生成逻辑。截图中的“远航第二次例会”是数据库已有普通待办，无法自动按自然月更新标题。

目标行为：

- 每月 5 日存在一条远航例会联谊待办；
- 标题格式为 `远航{中文月份}例会+联谊`；
- 例如 2026-08-05 为“远航八月例会+联谊”，2026-09-05 为“远航九月例会+联谊”；
- 月份跨年后继续按自然月生成；
- 当前 2026-08-05 的旧例会记录原位更新，不新增重复记录。

## 采用方案

在现有 `ensureAutomaticTodos()` 中增加远航月度例会保障逻辑，沿用生日提醒的“读取首页或待办列表时补齐”机制：

1. 以中国标准日期计算最近一个尚未过去的每月 5 日；
2. 使用确定性业务 ID `todo_yuanhang_monthly_meeting_YYYY_MM`；
3. 生成标题、日期、`会议培训` 分类、远航组织 ID、系统创建者和自动生成标记；
4. 如果同一日期存在标题为“远航第二次例会”或目标格式的远航例会记录，则复用并更新该记录；
5. 如果已存在确定性记录，只校正系统管理字段和标题，不覆盖完成状态、人工补充的地点、时间或说明；
6. 如果没有匹配记录，再创建新记录。

自动创建和自动更名均记录操作日志，操作主体标记为系统月度提醒，保留审计证据。

## 日期与重复控制

- 当天早于或等于 5 日时，目标为当月 5 日；晚于 5 日时，目标为下月 5 日。
- 同一自然月始终得到同一个确定性 ID，因此重复刷新不会产生多条系统待办。
- 兼容旧记录只匹配远航组织、同一天及明确的例会标题，不接管同日其他人工待办。
- 已完成的月度记录不重新打开，不改回待处理状态。

## 本地兜底

为保证云函数不可用时的演示行为一致，在小程序本地 API 兜底中增加同样的纯函数日期和标题生成逻辑，但不直接访问数据库，也不绕过线上云端权限。

## 测试与验收

- 2026-07-31 生成 2026-08-05，“远航八月例会+联谊”。
- 2026-08-06 生成 2026-09-05，“远航九月例会+联谊”。
- 12 月跨年后生成次年 1 月标题“一月”。
- 重复执行不产生重复待办。
- 旧“远航第二次例会”记录被复用，完成状态和人工字段得到保留。
- 执行云函数和相关前端文件语法检查、相关测试、完整测试及 `git diff --check`。
- 修改涉及 `cloudfunctions/api`，线上验证前必须重新部署 API 云函数；本地兜底代码变化也要求重新上传小程序版本。
