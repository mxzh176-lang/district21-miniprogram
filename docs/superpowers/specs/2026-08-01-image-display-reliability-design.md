# 全链路图片可见性修复设计

## 目标

从整体角度解决“图片已经上传，但在业务页面不显示”的问题，不为某个事件 ID、某两张图片或某一页写特例。修复要覆盖经 `uploadOrgFile()` 上传的图片从上传记录、资源关联、授权查询、临时链接解析到页面渲染的完整读链路。

首批验收必须包含截图中的远航历史事件，但它们只是真实数据样本，不是修复边界。

## 合规与权限

本次调整分类为 `review-safe`。

- 只修复内部组织档案和组织图片的已有展示能力，不新增公开发布、社交、评论或开放式 UGC。
- 所有页面继续通过 `miniprogram/utils/api.js` 读取业务数据。
- 所有上传继续通过 `uploadOrgFile()` 并创建 `file_records`。
- 云函数先确定用户可见资源 ID，再查询图片；不会因为恢复图片而扩大跨组织可见性。
- 不修改生产数据、不迁移或批量重写旧记录、不放宽写权限。

## 现状与问题边界

上传入口已经统一，但读取与展示链路仍然分散：

- 历史事件主要从 `event_image` 读取，并用 `file_records` 恢复旧数据。
- 首页轮播图从 `home_banners` 读取。
- 服务队云盘从 `media_album` 和 `file_records` 读取封面与文件。
- 成员头像和旧活动照片又使用各自的字段和返回模型。
- 代码中同时存在 `fileId`、`fileID`、`imageUrl`、`src` 和 `url` 等表示方式，临时链接解析也有多套实现。
- 部分查询同时依赖多个条件、固定上限或串行分批；当历史数据增多、缺少组合索引或单批失败时，可能把已存在的图片返回为空。

已确认的真实样本“2026-2027年度远航服务队队长会议”在 `event_record` 中的 `imageCount` 为 2，说明问题发生在上传意图之后的关联或读取链路，不能简单归因为该事件没有上传图片。

## 设计方案

### 1. 建立图片读取契约

云函数内建立可复用的图片识别与临时链接解析边界：

- 输入允许兼容现有数据中的 `fileId` 和 `fileID`，以及历史外链 `imageUrl`。
- 内部始终保留稳定的云文件标识，不把有时效的临时 URL 写回数据库。
- API 返回统一的可展示地址，同时保留稳定标识供编辑和再保存使用。
- 临时链接按平台上限分批并发解析，单批失败只影响该批，不将其他已成功图片清空。

### 2. 先授权，后按资源 ID 取图

对需要从关联表找图片的功能，采用统一步骤：

1. 按现有权限逻辑得到当前用户可见的事件、相册或其他资源 ID。
2. 只用这些已授权 ID 分批查询 `event_image` 或 `file_records`，避免先扫全表。
3. 查回后在云函数中再校验 `organizationId`、`resourceType`、`status`、文件类型和资源归属。
4. 主关联不完整时允许用同一资源的有效 `file_records` 恢复展示，但不允许跨组织或跨资源类型回退。

这一设计避免把正确性依赖于特定复合索引，同时保留服务端的最终鉴权。

### 3. 逐功能核对读写对称性

对每个使用 `uploadOrgFile()` 的图片功能建立“上传记录 → 业务关联 → API 返回 → 页面渲染”契约测试。当前纳入：

- 历史事件列表、首页最新归档、档案详情和编辑回显。
- 首页轮播图的展示与再编辑。
- 服务队云盘的相册封面和相册内图片。
- 成员头像。
- 仍在小程序中可达的旧活动照片页面。

只修改经证据确认存在同类读链路缺陷的模块；已经符合契约的模块只补测试，不做无关重构。

## 错误处理与可观测性

- 查询或临时链接解析失败时，云函数记录包含模块、资源类型、批次和数量的警告，但不记录临时链接或个人敏感信息。
- 某一图片源失败时，已成功的图片仍正常返回；对有稳定云文件标识的记录保留安全回退值。
- 图片记录与已授权资源对不上时直接丢弃，不以“尽量显示”为理由放宽数据隔离。
- 前端继续展示现有空态，本次不新增会泄露存储路径或内部错误的用户提示。

## 测试与验收

### 自动化测试

- 先为每一类已确认缺陷写失败测试，再修改实现。
- 覆盖 `fileId` / `fileID` / `imageUrl` 历史字段兼容、分批、分页、部分批次失败和临时链接解析。
- 覆盖大于单次查询上限的历史数据，确保后面的资源不会因固定 `limit` 消失。
- 覆盖组织、资源类型、状态和文件类型隔离，确保回退不导致越权图片混入。
- 覆盖历史事件、轮播图、云盘、头像和旧活动页的读写契约。

### 云端验收

在用户另行确认部署 `api` 后，先做只读验收：

- 截图中“2026-2027年度远航服务队队长会议”返回 2 张可显示图片。
- 再抽查至少一个旧事件、一个轮播、一个云盘相册和一个头像记录，确认 API 返回的地址可用。
- 用无权组织请求做反向验证，确保没有跨服务队读取。
- 不修改生产数据，不上传新图片。

云端读取通过后，再由用户决定是否上传新的小程序体验版。

## 非目标

- 不为指定事件、指定图片或指定用户写特例。
- 不批量迁移、修复或删除生产数据。
- 不调整图片数量上限、上传交互、档案内容或业务权限。
- 不自动部署云函数，不自动上传体验版、提审或发布。
