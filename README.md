# 21纪事本

21纪事本是二十一协作区和四个服务队的内部工作台：用待办推动服务，用档案沉淀历史，用成员和权限保证“谁负责，谁维护”。

它不是公开社区、论坛、社交平台或内容发布平台，而是一个面向内部成员、岗位负责人和管理员的组织协作与档案管理工具。

## 一句话产品逻辑

```text
当前空间 → 我的待办 → 完成记录 → 归档事件 → 历史展示 / 荣誉统计 / 照片沉淀
```

整个小程序应围绕这条主线收口：

- 当前空间决定用户正在查看协作区还是某个服务队。
- 待办负责推动未来要完成的事情。
- 完成后的待办形成记录。
- 记录进入档案与历史事件。
- 历史事件再支撑荣誉、照片和组织沉淀。

## 当前空间

“协作区 / 领航 / 爱领航 / 远航 / 精英”不只是筛选条件，而是整个小程序的当前工作空间。

切换空间后，以下内容应同步变化：

- 首页统计
- 待办列表
- 档案目录
- 最新归档
- 历史事件
- 成员名单
- 负责人和参与人选择范围

协作区空间展示协作区全局内容；服务队空间展示该服务队自己的成员、待办、档案和历史。

## 页面职责

### 首页

首页是“我的工作台”，不应该只是静态展示页。

普通成员主要看到：

- 当前空间
- 最新归档
- 通知
- 可查看的历史和档案

管理员、服务队管理员、岗位负责人主要看到：

- 我需要处理的待办
- 我负责维护的档案入口
- 待确认、待授权或待完善事项
- 最近归档内容

### 待办

待办是未来要做的事。

推荐逻辑：

```text
创建待办 → 分配负责人 / 参与范围 → 完成待办 → 生成归档事件
```

待办不应和历史事件混成一套概念。用户应该能清楚知道：

- 待办是未发生或正在推进的事。
- 历史事件是已经完成并归档的事。

### 档案

档案页是长期资料空间，不是单纯列表页。

建议结构：

1. 当前组织或服务队概览
2. 最新归档事件
3. 荣誉事件统计
4. 岗位档案栏目

档案栏目按岗位和职责维护。负责人可以维护自己负责的栏目，普通成员只查看授权范围内的内容。

### 成员

成员页承担三个核心能力：

- 找人：查看成员属于哪个服务队、什么岗位。
- 选人：为事件参与人、文档负责人、岗位负责人提供选择来源。
- 关怀：生日等低敏内部关怀信息。

成员页不应采集身份证、人脸、家庭地址、手机号等非必要敏感信息。

### 我的

“我的”页面用于身份识别和内部管理入口：

- 当前身份
- 所属组织
- 成员编号
- 内部资料完善
- 通知、历史、权限中心等入口

普通成员不应看到新增、删除、授权等管理能力。

## 权限原则

权限系统可以复杂，但用户感知必须简单。

面向用户的一句话原则：

```text
谁负责这个栏目，谁就能维护这个栏目。
```

底层权限按以下维度共同判断：

- 人员
- 组织
- 角色
- 岗位
- 模块
- 任期
- 操作类型

页面隐藏按钮不是权限控制。所有写操作必须由云函数再次校验。

## 荣誉逻辑

荣誉不应凭空录入，而应来自已归档事件。

推荐链路：

```text
归档事件 → 评定五星 / 四星 / 三星 / 二星 / 一星 → 进入荣誉墙
```

这样荣誉统计才有来源，历史事件也能真正成为组织沉淀。

## UI 方向

当前 UI 方向采用飞书式工作台风格：

- 浅色背景
- 白色卡片
- 蓝色主操作
- 清晰层级
- 弱阴影和轻边框
- 管理动作不干扰普通浏览

这个项目不适合过度炫酷、重渐变或强发光风格。它更像一个可信、清爽、长期使用的内部办公系统。

## 审核与合规底线

本项目长期保持“内部组织管理工具”定位。

禁止新增：

- AI 助手
- 公开发帖
- 评论
- 点赞
- 关注 / 粉丝
- 公开聊天室
- 论坛
- 开放式用户生成内容
- 支付、募捐、交易能力
- 非必要敏感个人信息采集

每次新增功能前必须确认：

- 是否仍符合个人主体小程序审核要求
- 是否扩大公开传播或社交属性
- 是否扩大个人信息收集
- 是否破坏服务队数据隔离
- 是否仍由云函数校验写权限

## 开发约束

- 页面统一调用 `miniprogram/utils/api.js`。
- 页面不得直接调用 `wx.cloud.database()`。
- 权限判断统一使用 `miniprogram/utils/permission.js`。
- CloudBase 专有调用只能放在 service、provider 或云函数层。
- 图片和文件上传必须使用统一上传服务。
- 修改 `cloudfunctions/` 后必须重新部署对应云函数。
- 纯前端样式和页面文案修改通常不需要部署 API。

## 发布说明

发布前必须确认：

- 工作区没有未确认的改动。
- 页面能在微信开发者工具正常编译。
- 普通成员不能看到管理入口。
- 管理员、岗位负责人只能操作授权范围内的数据。
- 没有 AI、公开社交、评论、论坛、开放聊天或公开 UGC。
- 如果本次改动涉及 `cloudfunctions/`，已经重新部署 `api` 云函数。

## 当前产品收口方向

后续开发优先围绕这六件事：

1. 当前空间切换
2. 我的待办
3. 最新归档
4. 档案栏目
5. 成员选择
6. 权限后台

不要为了“功能更多”而偏离主线。21纪事本的价值在于把服务队的事情做完、留下记录、沉淀历史，并让对应负责人可以长期维护。
